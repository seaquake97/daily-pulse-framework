二、本轮深度修复（五个真 bug，全部有实测证据）

1. 详情页「永不加框」接线断裂（最深根因）

publish 步骤 4.1 渲染 md 产出详情页后没有回写 entry["html"]，导致 entries.json 记 html: null → frame_pass 只加框 html 非 null 的条目 → 渲染产物永不加框、不进导航。表现为：fund-guide 等页面的 <pre> 不在 .doc 容器内，长代码行直接撑破页面（320px 视口 sw=625）。修复：渲染成功即回写，5 日期全部重建，21 篇详情页 100% 加框（class="doc" + data-df="v1" + detail-frame 三标记齐全）。

2. tag-gap 连字符复合类触发 frame_pass C-14 FATAL

统一渲染器 v1.1 用 class="tag tag-gap"，而 frame_pass 的 C-14 门禁把「site_blocks.css 有定义但未登记的交叉类」判为 FATAL（构建失败）。后端工程师将渲染器重构为 104 行薄门面 + md_render/ 包（5 文件 758 行），缺口徽章改用 .tag gap 双类；我同步把 site_render 三处与 site_blocks 规则统一为双类，扫描器计数口径同步更新，消掉框架页未来的同款雷。

3. 涨跌停统计三 emoji 保守保留缺口

fund-guide 市场宽度清单的 ➖ 平盘 / 🔥 涨停 / ❄️ 跌停 是内容位 emoji， sanitizer 正确识别为「未映射 → needs-manual-review 保守保留」，但一直没人补映射。本轮补映射为 minus / trending-up / trending-down（与全站红涨绿跌口径一致），needs-manual-review 归零，可见文本一字不删，并补回归测试锁死。

4. kpis breakout 负 margin 被简写清零（1152px 专有溢出）

.doc .kpis 的 margin: 0 0 var(--space-6) 简写，在同特异性下覆盖了 breakout 规则的 margin-inline: calc(var(--doc-breakout) * -1)（后者胜）。宽元素探出设计失效：1152px 视口下 kpis 右溢出 64px（sw=1216）。改 margin-block 双长写后 16 档宽度全部归位；cc-snap-grid 同款隐患一并修复。

5. 导航触达高度 23px（Apple HIG 44px 未达）

全站导航链接实测高 23px。加 min-height: var(--nav-h) 后达标 44px；窄屏（≤640px）导航英文段整体隐藏 + 收紧间距，320px 视口不再有链接溢出；详情页「返回」链接去掉重复日期（日期已在面包屑），320px 可视区完整。
