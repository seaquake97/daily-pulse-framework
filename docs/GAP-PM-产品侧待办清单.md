**第7 条与前六条性质不同**：前六条是「读法错了」（拍平文本、只看标题、外推 MD5），**这一条是「载体检索不足」**——本站同时发布三种载体，验证命令没有区分：

| 载体 | 脱敏路径 | `grep` 一个结论能否覆盖 |
| --- | --- | --- |
| HTML body | 经 sanitizer 的 pass 链 | — |
| `.md` 原文产物 | **不经 body pass**，是渲染前快照 | **否** |
| `feed.json` | 机读出口，独立生成 | **否** |

**共同病根：读文本而非读结构、查消费端而非查定义端、用断言代替事实源、看标题不看正文、从「同一文件」外推「同一内容」。** 这与「字段对了、页面没对」是同一个问题——**在��己做的核对工作上，我也反复犯了同型错误**。前五条已在对应章节就地更正，此处留档以便后人对照。

## 2. 真实产物核对：六个维度的产品缺口

### 2.1 信息完整性 —— 用户能否在一屏内回答「今天该做什么」

**结论：不能。首页首屏完全没有回答这个问题。**

实测首页 hero 区文本（`_git_pulse/docs/index.html`）：

```
数据驱动的 A 股 / 基金每日研判档案
每交易日的判断，留一条可回溯的轨迹。…
5 期归档 · 最近更新 2026-10-16（周五 · Fri）
已归档交易日 5 期 | 研判产出 21 篇
最近一期 Σ 评级 ▲ 均衡 | 最近一期 Σ 值 +0.180
```

- 全文检索：`今日` = **False**、`该做什么` = **False**、`建议` = **False**
- 首屏给的是「最近一期 Σ 值 +0.180」——这是**归档元数据**，不是「今天该做什么」。用户要读到第 3 屏以后才看到 09:28 那条任务卡。
- 日期页稍好：有「当日结论速览（按时点分组）」，10-16 呈现 4 张卡片（`股票助手/基金盘面` 竞价组 + 盘中组 + `每日总复盘` 收盘组），但**缺失的第 5 个任务不在速览里**（`股票复览` 出现 0 次）。

**缺口本质**：首页是「档案馆陈列」，不是「今日仪表盘」。对一个每天回访的用户，最有价值的一屏（今天该做什么）恰恰是最弱的。

### 2.2 可发现性 —— 3 次点击内能否找到任意一天/任意一篇

**结论：内容本身可达性优秀（1~2 次点击），但归档入口是死链。**

实测 BFS（从 `index.html` 起，按目录 `index.html` 解析）：

| 指标 | 实测值 |
| --- | --- |
| 可达 daily 文件数 | **26 / 26（100%）** |
| 深度分布 | 深度 1：21 个；深度 2：5 个 |
| 不可达文件 | **0** |
| sitemap URL | 10 条，覆盖全部 5 个日期 + 3 个栏目 |

**但按 HTTP 语义重新检测，全站 529 条相对链接中有 80 条是死链**：

```
index.html            -> ./weekly/     （目录存在，但无 index.html）
index.html            -> ./monthly/    （同上）
```

- 实际产物只有 `weekly/2026-W42/index.html` 与 `monthly/2026-10/index.html`，**没有 `weekly/index.html` 与 `monthly/index.html`**
- 这个导航出现在**每一个页面**（首页、方法论、订阅页、全部 21 个日期页、全部详情页、周报页、月报页）——即 **站内主导航的「周报」「月报」两个入口全站 100% 失效**
- 首页还提供 `sitemap.xml` 里的 `weekly/2026-W42/` 可用，所以搜索引擎能进，但**用户点导航进不去**

**现有测试为何没抓到**：`test_site_links.test_all_internal_hrefs_resolve` 的判定是

```python
ok = resolved.exists()
if not ok and href.endswith("/"):
    ok = (resolved / "index.html").exists()
```

目录本身 `exists()` 返回 **True**，断言在此**短路**，第二行永远不执行。这是典型的「测试通过但守护失效」——**它守的是文件存在，不是 URL 可达**。

### 2.4 可对比性 —— 跨日期、跨任务能否对比

**结论：有轨迹表，但周报与月报是同一份内容，且无跨任务对比。**

### 2.5 失败态体验 —— 降级、缺任务、评级缺失时用户看到什么

**结论：三种失败态里有两种是「静默消失」，最危险的一种是「自相矛盾」。**

| 失败态 | 实测用户所见 | 是否可理解 |

## 4. 诚实声明：这轮不打算做什么，为什么

以下是我**主动放弃**的机会，明确写出来以免被当成遗漏，也避免为了凑数把小事包装成缺口。

### 4.1 不做：搜索功能（站内搜索框）

首页 `has search input: True` 但**无任何搜索逻辑**（零 JS 是 PC-21 的硬约束，且 `has 搜索 text: False`）。看起来像缺口，但我不建议做：

- 站内总量 5 天 21 篇，BFS 实测**全部 1~2 次点击可达**，用户不需要搜索
- 唯一合理形态是「按持仓标的搜索」，而这实质是 PM-10（标的档案页）的一部分，不是独立功能
- 在 26 个文件的站点上加搜索框，是为不存在的需求增加界面元素——违反 D-26 克制感

**结论：不做。** 若 PM-10 落地，标的检索由标的档案页承担。

### 4.2 不做：评论区、点赞、收藏、登录

这是**个人独立运营的非持牌内容站**（页脚已声明），不是社区产品。加评论即引入内容审核、垃圾信息、隐私合规成本，而用户诉求里没有任何一条提到互动。

**结论：不做。** 与用户「我只想知道今天该做什么」的原始诉求完全无关。

### 4.3 不做：跨日期 Σ 折线图

当前「评级轨迹总览」已是表格，且 `comparable:false` 的限制被诚实标注了 93 处。画 Σ 折线图在数据准许时会误导读者做跨时点比较（PC-13/PC-14 正在解决这件事）。

**结论：不做图表。** 数据口径未统一（OPEN-001 未定案）前，表格比图表更诚实。等聚合口径定了再评估。

### 4.4 不做：日/周/月报以外的「季报/半年报」

5 天数据量下，季度粒度只有 1~2 个点，无聚合意义。属于典型的「为了有而加」。

**结论：不做。**

### 4.5 不做：合规与免责相关的一切改动

用户已明确指示「暂不用考虑」。本文不列相关待办，扫描器数据仅用于判断 P0 技术规则（emoji）是否被突破，不涉及合规内容本身。

### 4.6 关于「17 条」的诚实说明

本期只列 17 条，其中 P0 10 条。我认为再往下拆会产出「把一件事拆成三条凑数」的东西——例如把「标的档案页」拆成「建页」「建数据」「建反向链接」三条，实际是一件事（PM-10，成本大）。**宁可少列，不注水。**
