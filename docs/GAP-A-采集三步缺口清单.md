## GAP-A1 · 取数层：从「LLM 手写 JSON」到「脚本组装 + 契约校验」

### 现状与缺口
- **缺口 1**：MCP 采集结果由 LLM 用 Write 工具**手写**成 market_data.json。字段名、类型、单位（亿/万/元）全靠模型自觉 → 同一份 schema 每天可能写法不同，validate 只能查部分字段。
- **缺口 2**：两个 HTTP 老脚本仍在任务目录里且**仍被 14:30 任务书引用**（步骤 2 提到「禁止复用 11:00 的 HTTP 脚本链」，说明它曾经被用）。它们不参数化、依赖 `/tmp` 缓存、关闭证书校验。
- **缺口 3**：无「采集清单」——每次该调哪些 MCP 工具、抓哪些字段、什么单位，全部散在任务书自然语言里。

### 目标形态
1. `engine/collect/market_data.schema.json`：market_data.json 的**权威 schema**（字段/类型/单位/必填/缺口声明）。
2. `engine/collect/assemble_market_data.py`：读 MCP 原始响应（落盘为 `mcp_raw/<date>.json`）→ 按 schema 组装 market_data.json → 调 validate。**LLM 只负责调 MCP 与落原始响应，不手写成品**。
3. `engine/collect/COLLECTION.md`：每个任务的采集清单（工具、字段、单位、缺口降级路径）。
4. HTTP 老脚本归档：`fetch_data.py` / 14:30 同名脚本移入 `_legacy_http/` 并在文件头标注禁用原因。

### 验收
- `python3 assemble_market_data.py --date X --raw mcp_raw/X.json` 对 5 个历史日期的原始响应重放，产出与现有 market_data.json **字段级一致**（允许数值尾差）。
- schema 校验：故意删字段 / 改类型 / 填字符串数字 → 必须报错并指出路径。

## GAP-A2 · 生成层：报告生成从「LLM 自由写」到「契约化骨架 + LLM 填内容」

### 现状与缺口
- **缺口 1**：15:05 股票复盘、15:30 总复盘**零脚本**，报告 md 完全由 LLM 自由撰写 → 章节结构、评级口径、结论位置每次都可能不同（这正是用户「风格不一致、看不出结论」的上游成因）。
- **缺口 2**：11:00 的 `generate_report.py` 读 `/tmp/market_data_cache.json`——**数据新鲜度不可控**（记忆里已有铁律：禁读该缓存），且 `/tmp` 会被清理，属隐性故障源。
- **缺口 3**：章节命名无契约（各任务 h2 各写各的），导致渲染层无法稳定映射「结论卡/免责声明/数据源」区块。

### 目标形态
1. `engine/report/report_contract.yaml`：五任务共用的章节骨架（每任务必填/选填章节 + 章节语义标签）。
2. `engine/report/check_report.py`：对产出 md 做结构校验（必需章节齐否、评级与 Σ 是否与 market_data 一致、观点是否带 eval_at、是否残留 emoji/HTML 尾巴）。
3. 改造 `generate_report.py`（11:00/14:30）：**数据来源改为 market_data.json 文件路径参数**（不再读 /tmp 缓存），产出 md。
4. 14:30/15:05/15:30 三任务：任务书改为「按 report_contract 章节骨架撰写」，并接 check_report 自检。

### 验收
- 对 5 个历史日期的 md 跑 check_report，报告当前不达标项（作为基线）。
- 故意删章节 / 改评级使其与 market_data 不符 → 必须报错。

### 本轮实测抓到的真实缺陷（非假想，均已修复）
| 缺陷 | 发现方式 | 影响 |
|------|---------|------|
| 5 份 market_data 缺 `data_stage` | 契约校验器扫全量历史 | 站点时点口径可能错标（靠发布层兜底才没出事） |
| 旧产物 `chg_pct` 单写法 | 同上 | 消费方读 `change_percent` 静默拿到 None，涨跌数据凭空消失 |
| 3 个降级轮正文仍给可执行动作 | 报告契约校验器 | 金融场景 P0：读者照做 |
| 「01 结论卡」被误判空章节 | 校验器误报 → 修正 | 分组 h2 自身无文字、正文在 h3 是合法结构 |
| 内联列表被逐字符拆分 | 校验器静默失效 | `verdict_keywords` 变成单字符序列，R-2 规则形同虚设 |
| 行尾注释未剥离 | 同上 | 规则带上说明文字，匹配失效但看不出异常 |
| 预检用导入时常量 | 环境变量覆盖失效 | 缺依赖漏检，错误跑到子进程才爆 |

## 纪律（实施时不得违反）
1. **禁止回退到 HTTP 取数**：所有新增采集走 MCP；现存 HTTP 脚本一律归档并标注禁用。
2. **禁止 /tmp 缓存**：中间产物一律落 `<任务目录>/<日期>/` 内，可追溯。
3. **禁止破坏现有发布链路**：`publish_to_github.py` 的退出码契约与 4 本任务书的调用方式保持不变（改路径须默认值等价）。
4. **每项必须有可执行验收**：不接受「已重构」这类无法机检的结论。
