## 一、痛点诊断与真机截图证据分析

根据用户提供的 iPhone 客户端实测截图（2026-10-17 12:49），当前移动端排版存在以下严重破坏使用习惯的问题：

1. **结构失序，信息未分层**：
   - 首页所有历史日期与每日全部时点全部平铺展开，页面垂直滚动条极长；
   - 用户无法按日期和时点有选择性地查看，缺乏原生金融 App 的层级把控感。
2. **标签大乱炖（严重视觉污染）**：
   - 在 `09:28` 竞价时点，右侧同时堆叠了 **5 个标签**：
     `[ 竞价时点 ]`、`[ ⚠️ 数据源降级 ]`、`[ ⚠️ 数据不可信·Σ 不作参考 ]`、`[ - 评级未标注 ]`、`[ ⓘ 统计口径不同 · 数值仅供参考 ]`；
   - 5 个大色块标签在窄屏下纵向叠成 5 行，彻底霸占了屏幕横向与纵向视觉重心，本末倒置。
3. **标题冗余废话连篇**：
   - 日期卡片标题已经写了 `2026-10-16 周五`，条目内部居然重复写 `股票助手 · 2026-10-16（周五）早盘竞价 →`；
   - 标题折成两三行，占满屏幕。
4. **决策信息倒置与微时间干扰**：
   - `11:00` 时点下方突兀出现 `生成 11:14`，干扰主时间阅读；
   - 评级与核心结论没有被第一眼看到，反而是大篇幅长句直接塞在列表页。
5. **底部遮挡**：
   - 页面底部未适配移动端安全边距，导致最后一个时点被浏览器底部地址栏遮挡。

## 二、核心方案：三级渐进展开手风琴架构（Three-Level Accordion）

将原先的平铺流彻底重构为符合移动端习惯的三级折叠结构：

```
Level 1: 【日期卡片】（如 2026-10-16 周五） -> 可展开/收缩
  │
  └── Level 2: 【时点卡片】（如 09:28 股票竞价） -> 可展开/收缩
        │
        └── Level 3: 【时点核心决策与指引】 -> 展开呈现核心动作与完整报告链接
```

### 2.1 Level 1（一级：日期卡片手风琴）
- **形态**：每一个归档日为一个折叠卡片（`<details class="day-accordion">`）。
- **折叠规则**：
  - **最新一期交易日**（数组 index == 0）：**默认展开（open）**；
  - **历史交易日**（index > 0）：**默认折叠收起**，仅露出一级头部；
  - 读者进入首页一眼看到最新交易日的所有研判，需要看昨天或历史，只需点一下历史日期即可平滑展开，不点绝不霸占屏幕。
- **一级头部（Header Row）**：
  - 左侧：日期与星期（`2026-10-16 周五`）
  - 右侧：当日综合评级徽章（`【均衡 ▲】`） + 当日综合 Σ（`Σ +0.180`）+ 展开收缩箭头

### 2.2 Level 2（二级：每日时点手风琴）
- **形态**：在展开的日期内部，展示 4~5 个核心时点（`<details class="slot-accordion">`）。
- **折叠规则**：
  - 每个时点也是一个可点击展开/收起的卡片；
  - 头部高度仅 **48px**，单手大触控热区（整行可点）。
  - **折叠态展示内容（Header）**：
    - 左侧：时点时间（`09:28`） + 精炼业务名（`股票竞价` / `基金盘面` / `基金指引` / `每日复盘`，**彻底剥离日期与星期**）；
    - 右侧：**单一状态药丸（Status Pill）**（正常为评级徽章 `进攻`，降级为 `⚠️ 降级`）+ 展开箭头。
  - 用户即便不点开任何时点，仅看这 4 行，就能在 2 秒内看清全天行情演进节奏！

### 2.3 Level 3（三级：时点研判与操作决策展开区）
- 点开某个时点后，轻量展开：
  1. **核心操作卡（第一视觉）**：
     - 大字加粗突出展示 `【标准动作】定投额度上浮 ≤20%，网格卖单档位可上移...`；
     - 降级态明确说明：`数据源降级，本轮标准动作暂不执行`。
  2. **关键分析佐证（第二视觉）**：
     - 精炼呈现关键事实，去掉大段折行废话。
  3. **完整报告快捷入口**：
     - `<a class="slot-detail-btn">查看完整研判报告 →</a>`，44px 高度，大按钮设计，便于拇指点击直达。

## 3. 标签与视觉元素极致精简规则

| 原有元素 | 现状问题 | 新规范（精简决策） |
|---|---|---|
| **评级徽章 + 降级标签 + 数据不可信 + 评级未标注** | 堆叠 5 个色块，严重混乱 | **单一状态药丸原则**：每个时点至多 1 个核心状态徽章。正常时为 `rating_badge`；降级时统一为 `<span class="badge badge-degraded">⚠️ 降级</span>`，绝不再堆叠同义标签！ |
| **统计口径不同 · 数值仅供参考** | 每个条目反复插入大黄框 | **从列表条目中彻底移除**！仅在日期卡片底部或页面顶部保留 1 处全局说明，严禁时点条目中重复插大膏药。 |
| **标题中内嵌日期与星期** | 标题长达 30 字，折成 3 行 | **纯函数精简提取**：剥离所有 `YYYY-MM-DD` 与 `（周X）`，精简为任务本质名（如 `股票助手 · 早盘竞价`），单行放得下。 |
| **生成微时点（如 `生成 11:14`）** | 读者不关心的工程抓取秒级日志 | 在列表折叠层彻底隐藏；仅在展开后的三级辅助信息中以微弱文字呈现。 |
| **底部边缘遮挡** | 贴底被 iPhone 导航栏盖住 | 容器增加 `padding-bottom: max(var(--space-16), calc(env(safe-area-inset-bottom, 24px) + var(--space-8)))`。 |

## 4. 验收标准（Acceptance Criteria）

1. **AC-1（三级结构）**：
   - 首页历史日期默认折叠收起，仅当天默认展开；
   - 时点条目支持独立展开/收缩；
   - 交互完全原生，零外部 JS 依赖，纯 HTML5 `<details>` + `<summary>` 实现。
2. **AC-2（视觉纯度）**：
   - 任意时点折叠头部至多仅有 1 个状态徽章，彻底杜绝多标签堆叠；
   - 标题完全剔除重复的年月日星期文本；
   - 列表折叠头部零微时点。
3. **AC-3（合规与团队铁律）**：
   - 团队 P0-1 铁律：100% 零 emoji 功能图标（统一采用项目已锁定的内联 SVG Symbol）；
   - 团队 P0-2 铁律：100% 零紫粉渐变；
   - 团队 P0-3 铁律：100% 走 Design Token，零硬编码颜色；
   - 全工程 27 套自动化测试保持 100% PASS。
