# ADR-006: 发布层缺失任务的退出码语义（非零退出而非静默 warn）

## Status: Accepted (2026-10-16)

## Background

A-03 实测：2026-10-16 15:05 的 `股票复盘` 目录整条没有 md/html 产物
（只有 5 个 JSON），`publish_to_github.py` 收集到 4 个 slug 后**退出码 0**
正常发布——站点时间线上当日复盘整格消失，读者与定时任务侧都看不到任何
告警。根因是 `collect()` 对缺失 slug 静默 `continue`，缺失信息在返回前
被丢弃（GAP-ARCH §6.2）。

ADR-005 决策四已把缺失分成四种语义，其中前两种（目录不存在 = 未运行；
目录在但候选文件全缺 = 运行了但无产出）都要求「退出码 2 + 告警」。本 ADR
记录该规格的**实现取舍**：为什么选非零退出而不是静默 warn，以及三个
实现边界如何处理。

## Decision

### 决策一：缺失即非零退出（2），且中止在 manifest 写入之前

`collect()` 返回 `(outputs, missing)`，缺失 slug 逐条带
`reason`（`dir-missing` / `no-artifacts`，对应 ADR-005 决策四的前两种
语义）。`main()` 在 `missing` 非空时：

1. stdout 打印「全部/部分任务产物缺失（实收 got/total）」，逐条列出
   任务名、slug、缺失原因与预期目录——全部缺失与部分缺失同用退出码 2，
   但行首的「全部/部分」与实收计数使两者在输出中可区分；
2. 返回退出码 2，**在步骤 4 落盘与步骤 6 manifest 写入之前**中止。

**为什么选非零退出而非静默 warn**：发布层的消费者是定时任务与推送代理，
它们只判退出码。退出码 0 等于「今天成功了」——缺一条复盘与五条全发在
退出码层面无法区分，静默 warn 只是把「内容缺口」换了个不会有人看的
地方沉默。这个缺陷比直接失败危险一个量级：站点看起来正常，读者以为
当日没有复盘。非零退出让缺失在**唯一被自动检查的通道**上显形。

**为什么中止在 manifest 之前**（对 GAP-ARCH §6.2「manifest 记
missing_tasks」的有意偏离）：`_stage/manifest.json` 是推送侧的唯一契约，
且按 stage 覆盖写。若失败轮也写 manifest，上一轮成功状态的 manifest
会被一份「缺了任务」的 manifest 覆盖，推送代理随后推上去的仍是不完整
产物——用失败 manifest 覆盖成功 manifest，是把「静默缺斤」升级成
「带契约的缺斤」。缺失信息由 stdout + 退出码 2 承载，对定时任务侧
（唯一自动消费者）完全充分；manifest 保持「最后一次成功状态」语义。

**为什么不加 `--allow-missing` 旁路**（对 GAP-ARCH §6.2 的有意偏离）：
MVP 阶段五个任务都是每日必跑项，没有「当日合理缺席」的任务。旁路开关
一旦存在，定时任务侧为了「不让流水线红」会加上它，重新制造静默缺口——
P0 修复的防线不应该自带绕过阀。ADR-005 决策四的第四种语义
（`settlement` 类可选任务）落地时，按该 ADR 用 `TASK_SOURCES` 的
optional 标记表达，不复用通用旁路。

### 决策二：`TASK_SOURCES["stock-review"]` 改指 15:30 目录（ADR-005 决策一的实施）

随 A-03 同链实施（GAP-PM §3.1 决策 1：「此项与架构师 A-03 同链」）：
`stock-review` 的候选文件从「股票复盘（15:05）目录的
`stock_review.md`/`.html`」改为「每日总复盘（15:30）目录的
`stock_review.md`」（只取 md，详情页由步骤 4.1 统一渲染）。15:30 目录
实测 4/4 交易日有产物，15:05 是可选副本（2026-10-16 整条消失即本次
事故日）。ADR-005 决策三的「同上源」渲染标注不随本改动落地，仍按该
ADR 的跟踪状态单独处理——本次只改发布源，不改呈现层语义。

## Consequences

正面：

- 定时任务侧只看退出码即可发现「当日有任务没产出」，缺失任务名、
  原因与预期目录直接进 stdout，运维不用翻目录。
- 不完整日的产物不进 `_stage`——「发布 4 条、看起来像成功」的事故形态
  （2026-10-16）不可能复现；修复缺失任务后同命令重跑，幂等。
- `stock-review` 改指 15:30 后，2026-10-16 成为完整五日，当日时间线
  补齐 15:05 格（需重新推送才上线，见发布说明）。

负面：

- 任一任务缺席即整日不发布：14:30 产物迟到时，15:35 的发布轮会失败，
  需补跑轮次（定时任务侧的行为契约变更，需确认重试策略）。
- 退出码 2 的语义从「无产出/参数错误」扩为「产物缺失（部分或全部）/
  无产出/参数错误」——调用方若按 2 做「跳过今日」处理，行为不变；
  按 2 做「参数错误告警」处理的会收到更具体的 stdout。
- `stock-review` 的 Σ 仍取自 15:05 目录的 `market_data.json`
  （`SLUG_DATA_DIR` 不在本 ADR 范围）；md 源在 15:30、数据源在 15:05
  的跨目录组合是既有设计，若两目录数据漂移需另立 ADR。
