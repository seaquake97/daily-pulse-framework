# ADR-004: 降级态的 rating/sigma 处置口径与目录型链接的可达判定

## Status: Accepted (2026-10-16)

## Background

PM 在 GAP-PM 清单中提出三个需要架构裁决的边界问题。本 ADR 记录裁决与实测证据。

裁决背景是三条已实测的既有事实：

1. `publish_to_github.py:368-375` 已确立「假值一律置 None」的范式——Σ 与 rating 缺失时
   诚实置 `None`，由渲染层出「数据缺口」徽章，严禁回落 0.0 或借用他值。
2. `site_render.py:270-277` 的徽章组装顺序是：`stage_chip` → `chip-pending`（无网页时）→
   `tag gap`（降级时）→ `rating_badge`（插到第 0 位）。rating 徽章**无条件**渲染，
   不看 `degraded`。
3. 全站零 emoji/零裸 hex 的 P0 纪律要求「降级产出不得看起来与正常产出一样」，
   而当前实现在降级卡片上同时输出降级标签与进攻徽章。

## Decision

### 决策一：目录型链接的可达判定统一要求 index.html

**判定规则**：对站内 href，若解析结果是目录，则该目录必须存在 `index.html` 才算可达。
目录本身存在不算可达。

**依据**：GitHub Pages 对无 `index.html` 的目录返回 404，不生成目录索引。
本地文件系统与 HTTP 服务器行为不一致——本地 `Path.exists()` 对目录返回 True，
掩盖了线上 404。这是「测试全绿但线上死链」的结构性成因。

**已实施**：`test_site_links.py` L-1 现为

```python
resolved = (page.parent / target).resolve()
ok = resolved.exists()
if ok and resolved.is_dir():
    # 目录不算可访问目标：GitHub Pages 只认 index.html。
    ok = (resolved / "index.html").exists()
```

**配套要求**：周报/月报总览页必须真实生成。`build_site.py:123-126` 已 emit
`docs/weekly/index.html` 与 `docs/monthly/index.html`，`site_pages.py:282` 的
`archive_index()` 负责其内容。产品判断是「导航有入口就得有页面」，
不采用「撤掉导航入口」的方案——撤入口会让信息更少。

### 决策二：降级态的 rating/sigma 一律置 None（不新增 degradedRating 字段）

**判定规则**：`e["degraded"] == True` 时，对**对外出口**的
`rating` / `sigma` 输出 `None`，且页面不渲染 `rating_badge`。

**依据**：采纳 PM 的倾向，理由是它复用决策一确立的既有范式
（`publish_to_github.py:375` 的 `rating, sigma, sigma_src = None, None, "missing"`），
处置逻辑同源、无需新增字段与新契约，且 `degraded=True` 已足以表达「本轮结论不适用」。
新增 `degradedRating` 会引入第二套评级字段，客户端需两套分支判断，
与「同一语义只有一个出口」冲突。

**实施落点（2026-10-16 实测修订，原措辞已作废）**：

| 层 | 做法 | 理由 |
|---|---|---|
| `site_pages.py:408-409`（feed 边界） | `rating: None if degraded else e.get("rating")` | 对外出口统一降级；`entries.json` 保留原始 verdict 值可追溯 |
| `site_render.py:284`（时间线卡片） | 改为 `if e.get("degraded"): ... elif rating is not None: meta.insert(0, rating_badge(rating))` | `if/elif` 结构天然互斥，比嵌套 `and not degraded` 更清晰 |

原方案写的是在 `publish_to_github.extract_entry` 与 `site_render.py:277`
两处分别判断。**实际实现改为在 feed 边界单点降级，优于原方案**：
上游 `extract_entry` 保留原始 `rating`/`sigma`，使 `entries.json` 仍可用于
事后追溯「当时算出了什么」；只有面向读者与客户端的出口做降级。
一处判断比两处判断更难漂移。

**关于 chip-pending**：PM 建议「复用 chip-pending 样式做降级徽章」。实测
`chip-pending` 已被 `site_render.py:273` 用于「网页版待补齐」语义，
不是未使用的空样式。降级标签应继续用 `tag gap`
（`site_render.py:275` 现状），不抢占 chip-pending 的语义位。

### 决策三：SLUG_STAGE 收敛为单一事实源，md_render 与发布层取值一致

**判定规则**：`stock-assistant` 的 stage 在**所有**映射表中统一为 `pre_open`。
当前存在三份定义，其中 `md_render/meta.py:40` 为 `intraday`（与另两份冲突）。

**实测依据**：上游 md 正文已自行声明 `data_stage: pre_open`，
`extract_meta()` 走 L2 启发式实测返回 `{'stage': 'pre_open', 'source': 'heuristic'}`，
因此当前 md 渲染路径**未**产出错标——这是运气，不是设计：
一旦 md 正文缺少该声明，L2 落空即回落到 `SLUG_STAGE["stock-assistant"]`，
产生与 `publish_to_github.py:129` 相反的标注。

**实施要点**：`md_render/meta.py:40` 的 `intraday` 改为 `pre_open`。
不改 `site_content.py:57-58` 的 `STAGE_MAP`——那里 `pre_open` 与 `intraday`
共用 `chip-intraday` 变体、用不同图标（`timer` / `clock`）区分，是正确的表现层设计。

**长期**：`SLUG_STAGE` 在 `publish_to_github.py:129` 与 `md_render/meta.py:39`
两份定义靠注释维系（`meta.py:22` 自陈「复制而非 import：反向 import 会把整条
发布管线拖进渲染进程」）。这个理由成立，但代价是两处可独立漂移。
建议方向：把 `SLUG_STAGE` 下沉为纯数据（JSON/YAML），两侧各自读取，
消除「复制两份」而非「消除依赖」。

## Consequences

正面：
- 目录型死链不可能再以「测试全绿」的形式通过，线上 404 与本地判定同构。
- 降级卡片不再同时表达「结论不适用」与「▲▲ 进攻」，金融场景的误导风险消除。
- feed.json（小程序/PWA 唯一数据入口）不再向客户端传递降级态的评级值。

负面：
- 决策二使降级条目在 feed.json 中 `rating=null`，客户端必须处理 null。
  这是契约变更，需与小程序侧同步（当前无小程序代码，ARCH-R6 尚未实现，
  因此本次变更零迁移成本）。
- 决策一使「只建目录不建 index.html」的中间态在测试中暴露，
  后续任何新增归档目录都必须同时产出 index.html。

待办联动：
- 决策三的长期项（SLUG_STAGE 下沉为数据文件）建议并入工程侧 A-09
  「引擎脚本迁入 framework/engine/signals/」一并处理，避免两次动同一处代码。
