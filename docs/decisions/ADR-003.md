# ADR-003：emoji → SVG 图标语义映射

## Status

Accepted（2026-10-14）

## Background

项目 P0 规则明确禁止 emoji 作为功能图标。2026-10-14 六任务产出实测残留：

为遵守 P0 禁令，本文件不直接展示 emoji 字符，改用码点标识。

| 任务 | emoji 数量 | 分布与码点 |
| --- | --- | --- |
| 基金每日操作指引（14:30） | 13 | 标题 U+1F4CA；章节 U+1F6A6 / U+1F4CB / U+1F3AF / U+1F4C8 / U+1F4BC / U+26A1 / U+1F30D / U+1F4DC；正文 U+26A0 U+FE0F |
| 股票复盘（15:05） | 4 | 决策卡 U+1F3AF ×4 |
| 基金每日盘面分析（11:00） | 1 | U+26A0 U+FE0F（企稳校验未通过） |
| 股票助手（9:28） | 0 | 无 |

问题不只是「不好看」。14:30 指引的章节结构完全靠 emoji 承载语义：

```
## <U+1F6A6> 核心决策：Σ 评级与 15:00 前干预指令总档位
## <U+1F4CB> 15:00 前干预指令清单（分层执行，禁止套话）
## <U+1F3AF> 核心决策卡（Decision Cards）
## <U+1F4C8> 一、全市场六维确定性信号硬校验结果
## <U+1F4BC> 二、基金组合持仓诊断与加权归因
## <U+26A1> 三、股票与场内 ETF 网格操作指引
## <U+1F30D> 四、外盘联动与全球市场企稳校验
## <U+1F4DC> 五、观点台账与次日验证跟踪
```

对照 CONTENT-SPEC.md §2.2，这八个章节在统一骨架中的规范名为：结论卡 / 网格委托指令 / 专家圆桌（日内 Σ 演进）/ 确定性信号明细 / 组合加权归因 / 网格委托指令 / 外盘联动校验 / 观点台账——八段中文标题对应八个语义键，而原文靠八个 emoji 承载语义，机器无法解析。

emoji 与章节语义混在一起，导致：章节名无法进入机器校验（以 U+1F6A6 开头的「核心决策」不是稳定标识）；同一语义在不同任务用不同 emoji（U+1F3AF 在 14:30 指决策卡、在 15:05 也指决策卡，但 U+1F4CA 只在标题出现）；屏幕阅读器朗读 emoji 名称而非语义。

同时项目内**已有一套做对的实现**：`publish_to_github.py` 的 `_TITLE_EMOJI` 正则在提取标题时剥离 emoji，`_clean_title()` 清理井号与 markdown 强调符。这说明项目已有共识，只是未覆盖正文与 HTML 渲染层。

另一处约束：站点 `build_site.py` 的 `RATING_ARROWS` 使用 `▲▲ ▲ ↔ ▼ ▼▼` 作为评级的色盲友好冗余编码。这是有意为之的可访问性设计，**必须保留**。

## Decision

**用「语义键 → SVG 图标」映射替代 emoji，只锁语义不锁实现。**

三层设计：

**第一层：语义键映射表。** `content_dictionary.ICONS` 定义 16 个语义键，每个给出中文语义与 24x24 线性描边 path。风格统一为：24x24 视框、线性描边、`stroke: currentColor`、随文字颜色变化。

关键约束：**契约只锁语义键与图标含义，不指定图标库**。渲染层可自行决定 inline `<svg>` / `<img>` / CSS mask 实现方式，只要语义键一致。跨任务混用不同图标库视为违规。理由：项目现无任何前端依赖，为一套 16 个的图标引入库不划算；而语义一致性才是协作真正需要的约束。

**第二层：emoji 白名单显式枚举，不用区间。** 判定由 `EMOJI` 规则执行。

这里有个必须记录的坑：**不能用 `U+2600-U+27BF` 区间覆盖**。该区间内含 U+2605、U+2606 等排版评分符号。若一并禁掉，会连带破坏 `build_site.py` 的 `RATING_ARROWS`（`▲` U+25B2 / `▼` U+25BC / `↔` U+2194）色盲友好设计。当前白名单分五段枚举：

| 段 | 码点范围 | 内容 |
| --- | --- | --- |
| 1 | U+1F300-U+1F5FF | 常用图形符号（实测全部命中） |
| 2 | U+1F600-U+1F64F | 表情 |
| 3 | U+1F680-U+1F6FF | 交通与地图 |
| 4 | U+1F900-U+1F9FF | 补充符号 |
| 5 | U+26A0 U+26A1 U+2705 U+274C U+2757 U+2753 U+2B50 | 杂项符号：仅取实际用作章节标记者 |

第 5 段刻意不写区间，改为逐个枚举，因为该区段内多数字符是排版符号而非 emoji。

实测结果：对 15 个真实 emoji 全部命中（零漏判），对 18 个排版/评级符号零误判（U+2605 / U+2606 / U+25B2 / U+25BC / U+2194 / U+2191 / U+2192 / U+2714 / U+2611 / U+2691 / U+260E / U+2702 / U+03A3 / U+00B7 / U+2014 / U+00D7 / U+00A7 / U+2460）。

**第三层：章节名脱离装饰。** 章节标题只保留规范中文名（ADR-001 锁定），语义由 SVG 图标在渲染层承载，不再把图标塞进 Markdown 标题文本。

配套：禁止紫色至粉色渐变。站点现有配色（`--accent:#b45309` 琥珀 + 中性灰）符合要求，保持不变，新增视觉一律在现有中性色板内取色。

## Consequences

正面：

- 章节名成为稳定标识，可进入机器校验（`SECTION_NAME` 规则已依赖这一点）
- 同一语义全局同一图标，满足一致性诉求
- 保留 `RATING_ARROWS` 的色盲友好设计，不因禁 emoji 而受损
- 不引入任何依赖

负面：

- 需为每个语义键手写 SVG path（16 个），比直接用 emoji 费工
- Markdown 源文件纯文本可读性下降：看到 `## 03. 确定性信号明细` 无法直接得知其图标语义，需查映射表

中性：

- emoji 白名单是白名单而非黑名单：新增 emoji 若不在五段范围内则漏判。缓解方式是每次新增章节标记时同步核对映射表
- 历史产出的 emoji 不回溯整改，与 ADR-001 的时间范围一致

## Alternatives Considered

**方案 A：直接引入图标库（如 Lucide 或 Font Awesome），按库内图标名映射。**
省去手写 path，但引入依赖与版本管理成本，且项目现无前端依赖体系；16 个图标自绘成本低于引入一套依赖的维护成本。并被否决。

**方案 B：保留 emoji，只统一用哪几个。**
改动最小，但违反项目 P0 规则。且章节名仍无法机器校验。并被否决。

**方案 C：按 `U+2600-U+27BF` 等标准区间一刀切。**
代码最短，但实测会误判 U+2605 / U+25B2 / U+25BC，破坏 `RATING_ARROWS` 可访问性设计。这是在开发中实际踩到的坑，已写入 `CONTENT-SPEC.md` §11 已知坑第 1 条。并被否决。

**方案 D：用 Unicode 符号（↑↓→←）替代 emoji。**
无依赖，但 `→` `·` `—` 等在正文中密度过高会干扰阅读，且语义不如 SVG 明确。并被否决。
