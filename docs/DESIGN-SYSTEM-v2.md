## §0 本文件的定位

用户说的三句话其实是**同一个病**：系统只定义了「长什么样」，没定义「什么必须一样」。

| 用户原话 | 真实病灶 | 本文件对应条款 |
|---|---|---|
| 深色模式观感差 | 表面层级没有契约，深色下靠「记得覆写」而非规则 | §D 深色模式契约 |
| 各个任务风格不一致 | 详情页骨架没有强制区块与顺序 | §A 详情页统一骨架 |
| 没有延续 Apple 设计风格 | 红线只写了「不要什么」，没写「必须是什么」 | §B Apple 设计语言红线 |
| 一致性思维没贯穿 | 没有可执行的交叉检查动作 | §C 一致性品控方法 |

**设计系统不是一份好看的样式表，是一份「差异必须被显式登记」的合同。**
本文件的每个编号条款都对应一个可机检或可目检的判据，不写无法验证的形容词。

## §D 深色模式契约

### D-1 四级表面原则

深色模式下，层级**只能**靠明度递进表达，**不能**靠投影（纯黑画布上投影不可见）。
任何组件的表面只允许取以下四级中的一级，不得新造：

| 级别 | 名称 | 浅色 | 深色 | 用途 | 与画布对比度（深色） |
|---|---|---|---|---|---|
| L0 | 画布 canvas | `#ffffff` | `#000000` | 页面底 | — |
| L1 | 抬升面 raised | `#f5f5f7` | `#1c1c1e` | 分组容器、时间线日组、块级代码 | 1.23:1 |
| L2 | 下沉面 sunken | `#f5f5f7` | `#2c2c2e` | 行内代码、输入框、次级填充 | 1.51:1 |
| L3 | 强填充 fill | — | `#3a3a3c` | 四级填充、禁用态 | 1.85:1 |

**组件在深色下的表面归属（强制，不得逐页自由发挥）：**

| 组件 | 深色表面 | 理由 |
|---|---|---|
| 时间线「日组」`.issue` | L1 raised | 一组多条，需要与画布切开的边界 |
| 时间线「单行」`.tl-item` | 无背景，仅 hairline | Apple 零卡片节奏，见 D-1.1 |
| 徽章 `.rating` / 芯片 `.chip` | 语义淡底（`rgba(色,0.16)`） | 已有实现，不改 |
| 详情页表格偶数行 | L1 raised | 见 D-2 |
| 块级代码 `.doc pre` | L1 raised | 见 D-4 |
| 行内代码 `.doc code` | L2 sunken | 见 D-4 |
| 结论卡 `.verdict-card` | L1 raised | 已有实现 |
| KPI 看板 `.kpis` | 无背景，仅 hairline | 已有实现 |
| 页脚 `.foot` | L1 raised | 已有实现 |

#### D-1.1 为什么不给单行加卡片（易被误改，写死）

根因是深色下 `--card-bg == --bg == #000000`。修法有两条路：

- ❌ 改 `--card-bg` 为 `#1c1c1e` → 每个 chip / tag / 徽章都变卡片，零卡片节奏被打破。
- ✅ **在「日组」这一层给抬升，行内保持无背景** → 层级可读，Apple 语言完好。

已按 ✅ 实施。任何「给单条时间线加卡片」的改动都违反本条。

### D-2 深色必须开斑马纹，浅色必须不开

`--table-zebra` 浅色 `none` 是**刻意的**：Apple 官方表格从不用斑马纹，靠 hairline 分行。
深色必须开，根因是数值实测：

```
--ap-dark-sep-soft #2c2c2e vs #000000 = 1.51:1
```

跨 5 列宽表时，1.51:1 的行分隔线不足以让读者把「第 3 行的数字」和「第 3 列表头」对应
（`evidence/dark-detail-1440.png` 底部「15:00 前干预指令清单」实测）。

取值 `--surface-raised (#1c1c1e)`，即 Apple 自家深色 inset list / 表格偶数行的官方值。
**不是** `rgba(255,255,255,0.03)` —— 后者在纯黑上等价 `#0f0f0f`，是自造第五级表面，破坏 D-1。

> **两套模式规则不同是有理由的，不是漏改。** 任何人「顺手把浅色也改成有斑马纹」即违反本条。

### D-3 结论三段式（跨 5 个任务的一致性锚点）

读者不点进详情页，也必须一眼知道「今天什么档、该做什么」。三段固定结构、三档权重：

| 段 | 类名 | 前景 | 字号 | 内容 |
|---|---|---|---|---|
| 段1 评级·Σ | `.concl-head` | `--fg`（最深） | 继承 `--fs-callout` | 均衡 / 冲突 / 防御…+ Σ 值 |
| 段2 标准动作 | `.concl-action` | `--fg-2` | 继承 `--fs-callout` | 今天该做什么 |
| 段3 关键事实 | `.concl-fact` | `--fg-3` | `--fs-footnote` | 触发条件 / 数值 |

**三段必须互不同色** —— 同色即权重失效，「结论先行」退化为普通段落。

**排版实现（v2 修订）**：`display:block` 行内流，**不是** `flex`。
flex + `wrap` 会让中文长句在段内被强行折断，且 `align-items:baseline` 在混排 11/13/17px 时基线漂移。
行内流让整段像一段话自然折行，分隔符随文字流动。段间距由 `.concl-sep` 的 inline margin 承担。

深色下分隔符 `--border` 仅 1.79:1，作为**结构**分隔（不是装饰）不可辨，故叠 `opacity` 抬升。

### D-4 代码块双层

块级 `pre` 与行内 `code` 不得同表面，否则整段代码在深色下与正文融成一片，分号/括号失去视觉锚点。

- 浅色：二者同为 `#f5f5f7`，靠 `pre` 的 1px hairline 分层。
- 深色：`pre` → L1 `#1c1c1e`；`code` → L2 `#2c2c2e`。

### D-5 对比度阈值表（脚本实算，非估算）

所有数值由 WCAG 2.1 相对亮度公式实算（`python3`，见本轮验证记录）。

| 内容类型 | 阈值 | 深色实测 | 判定 |
|---|---|---|---|
| 正文 `--fg` | ≥ 4.5:1 | `#f5f5f7` on `#000` = **19.29:1** | 通过 |
| 次级正文 `--fg-2` | ≥ 4.5:1 | `#a1a1a6` on `#000` = **8.16:1** | 通过 |
| 三级/元信息 `--fg-3` | ≥ 4.5:1 | `#86868b` on `#000` = **5.80:1** | 通过 |
| 强调 `--accent` | ≥ 4.5:1 | `#2997ff` on `#000` = **6.96:1** | 通过 |
| 占位 `--fg-muted` | 仅 ≥17px | `#6e6e73` on `#000` = **4.14:1** | 受限使用 |
| **占位落在抬升面** | ≥4.5:1 | `#6e6e73` on `#1c1c1e` = **3.36:1** | **不通过 → 见下** |
| 图形/边界（非文本） | ≥ 3:1 | `--ap-dark-sep #38383a` on `#000` = **1.79:1** | **不通过** |

**两条实测未达标的处置（写入使用禁区，不再新增例外）：**

1. `--fg-muted` 在 L1 抬升面上仅 3.36:1 → **禁止**用于任何承载结论或数值的文本，
   仅限 ≥17px 非关键文本与 placeholder。
2. `--ap-dark-sep` 1.79:1 < 3:1 → 承担结构职责的描边（表头下沿、分格线），
   文字侧必须由 `--table-head-fg` / `--fg-3` 提亮兜底，**不能**指望描边自己解决可读性。

### D-6 深色常见错法清单（本次事故沉淀，每条都是真发生过）

| # | 错法 | 后果 | 守护 |
|---|---|---|---|
| 1 | **浅色原语漏写深色覆写** | 黑底近黑字，对比 1.1:1 完全不可读 | `test_dark_mode.py` D-1 契约（本轮已修 5 个：tl-title / tl-summary / tl-kicker / tl-dot-stage-close / foot-fg） |
| 2 | 把「记得覆写」当设计系统 | 每加一个 token 就是一次漏覆写机会 | D-1 四级表面表穷举组件归属 |
| 3 | 深色沿用浅色斑马纹决策 | 1.51:1 行分隔，宽表读不出列对应 | D-2 |
| 4 | 深色自造表面色（如 `rgba(255,255,255,.03)`） | 第五级表面，两套模式规则打架 | D-1 |
| 5 | 深色给列表行加卡片 | 零卡片节奏破坏 | D-1.1 |
| 6 | 深色用投影做层级 | 纯黑上不可见，等于没做 | D-1 |
| 7 | 深色沿用浅色强调色 | 蓝 `#0071e3` on `#000` = 3.13:1，链接读不清 | 已有 `--accent: #2997ff` 覆写 |
| 8 | 代码块与行内代码同表面 | 深色下代码与正文融为一体 | D-4 |

## §A 详情页统一骨架（A-x 编号）

**全部 5 个任务的详情页必须共用此骨架。** 缺区块 = 构建期不通过，不是「建议」。

### A-1 必备区块与固定顺序

```
┌─ A-2 面包屑 ────────────────────────┐
├─ A-3 标题区 ────────────────────────┤
├─ A-4 doc-meta 元信息条 ─────────────┤
├─ A-5 结论卡 ────────────────────────┤
├─ A-6 正文（.doc）───────────────────┤
├─ A-7 页脚声明 ──────────────────────┤
└────────────────────────────────────┘
```

**顺序不可换。** 依据：读者路径是「我在哪 → 这是什么 → 什么时候的数据 → 结论 → 细节 → 免责」。

| # | 区块 | 选择器 | 必备 | 缺失后果 |
|---|---|---|---|---|
| A-2 | 面包屑 | `.doc-crumbs` | 是 | 详情页失去返回路径 |
| A-3 | 标题区 | `.doc-title` | 是 | — |
| A-4 | 元信息条 | `.doc-meta` | 是 | **不可接受**：读者无法判断数据新鲜度 |
| A-5 | 结论卡 | `.verdict-card` | 是 | 违反「结论先行」产品原则 |
| A-6 | 正文 | `.doc` | 是 | — |
| A-7 | 页脚声明 | `.footer-note` | 是 | **不可接受**：文章级免责缺失 |

### A-2 doc-meta 必备字段（6 项，缺一不可）

固定顺序：`调度时点 · 数据时点 · 评级 · Σ · 口径`

**实现类名（已核对产物，非杜撰）**：元信息条是 `.doc-meta` 容器，其下**复用时间线的既有组件**
（`.df-time` / `.chip-*` / `.rating-*` / `.tl-sigma` / `.tag-*`），
所以「同一份数据在首页和详情页长得一样」是结构保证的，不是靠人工对齐。

| # | 字段 | 实际类名 | 必填 | 说明 |
|---|---|---|---|---|
| 1 | 调度时点 | `.df-time` | 是 | 这个任务几点该跑（如 `调度 09:28`） |
| 2 | 数据时点 | `.chip-intraday` / `.chip-close` | 是 | 数据截止到几点（`盘中时段`/`竞价时点`/`收盘时点`） |
| 3 | 评级 | `.rating-*` | 是 | 五档之一（进攻/均衡/冲突/防御/回避） |
| 4 | Σ | `.tl-sigma` | 是 | 综合评分，带符号 |
| 5 | 口径 | `.tag` / `.tag-warn` / `.tag.gap` | 是 | 统计口径说明 / 缺口标注 |
| 6 | 任务归属 | `.df-kicker` | 是 | 这是哪个任务产的（位于标题上方） |

> 「调度时点 ≠ 数据时点」是这个站的核心信息价值。A-4 是唯一承载它的地方，**不可省**。
> 若上游 md 未提供生成时点，当前实现**不单列**——此时以 `.df-time` 的调度时点 + 数据时点芯片二者并存为准，
> 不得为了凑字段而伪造生成时点。

### A-3 各区块的高度 / 间距 / 字号阶

| 区块 | 上下间距 | 内部行高 | 字号阶 | 其他 |
|---|---|---|---|---|
| A-2 面包屑 | `--space-4` | `--lh-footnote` | `--fs-footnote` | `--fg-3` |
| A-3 标题区 | `--space-5` | `--lh-title2` | `--fs-title1` (34px) | `--fg`，`--tracking-title1` |
| A-4 doc-meta | `--space-4` | `--lh-subhead` | `--fs-footnote` | 芯片横排，间距 `--space-2` |
| A-5 结论卡 | `--space-6` | `--lh-callout` | `--fs-callout` | `--surface-alt` 抬升 + `--card-pad` 内距 |
| A-6 正文 | `--space-8` | `--lh-body` | `--fs-body` (17px) | 行宽 `--container-prose` 680px |
| A-7 页脚声明 | `--space-8` | `--lh-footnote` | `--fs-caption1` | `--fg-3`，顶部 1px `--separator` |

**全局字号阶（11 级，已是 Apple 二元字重下的合理上限，不得再增）：**

```
34 → 28 → 22 → 20 → 17 → 16 → 15 → 13 → 12 → 11
title1  t2    t3    t4    body  call sub  foot cap1 cap2
```

新增字号 = 违反 Apple 视觉韵律。层级不够时用**字重（400/590）+ 颜色**解决，不加字号。

### A-4 区块级要求

- **A-3 标题区**：`--fs-title1` 起头，`letter-spacing` 负值收（`--tracking-title1`）。
  中文标题超 20 字钳制两行（`-webkit-line-clamp:2`），不撑破布局。
- **A-5 结论卡**：深色下必须是 L1 抬升面（`--surface-alt`），禁止纯黑卡片。
- **A-6 正文**：
  - 数据宽元素（表格 / KPI / 双栏）按 `--doc-breakout` 探出，行宽不变。
  - `blockquote` 用 2px 左侧细线，**不是** 6px 彩色侧条纹（P0 禁令）。
  - 代码块按 D-4 双层。
- **A-7 页脚声明**：与站点页脚同形制，但字号降一级、颜色降一级。

### B-3 本轮目检发现的白名单（避免误判为违规）

以下两项**命中检测正则但属合法保留**，写清楚以免后续反复误报：

| 项 | 实测 | 判定 | 依据 |
|---|---|---|---|
| `saturate(180%) blur(20px)` | 命中 1 处 | **合法** | 是 `--nav-blur` 令牌定义（`design-tokens.css` L326），即 Apple localnav 官方粘性导航做法。**不是**装饰性毛玻璃卡片 —— 站上 0 处 `backdrop-filter` 玻璃卡片 |
| `♟️` U+265F | 24 处 | **合法** | IP_MARK 个人 IP 品牌标识，属 UGC 性质的署名标记，非功能图标。固定 20px 盒 + 15px 字，不随上游正文放大 |

### B-4 ⚠ 本轮发现真实 P0 缺陷：emoji 泄漏到 `<head>`

目检 emoji 时发现的**代码审查看不出来、只有真读产物才暴露**的问题：

```
源头：_stage/docs/daily/2026-10-13/stock-review.md
      「上证指数：3800.86 🔺 +0.10%」/「科创50：1427.18 🔺 +0.03%」
产物：stock-review.html  body 内 🔺 = 0（已正确转 SVG ✅）
                          <head> 内 🔺 = 2（og:description / meta description ❌）
```

**根因**：`sanitize_body.py` 的 emoji→SVG 只处理 `<body>` 子树；
`<meta name="description">` 与 `<meta property="og:description">` 由另一条路径从 md 首行生成，
**未经过同一套 emoji 净化**，于是原始 🔺 直接漏进 `<head>`。

**影响**：
- 违反 P0-1「零 emoji」（虽然它不是功能图标，但在 head 里以裸 emoji 出现）
- 社交平台分享卡片（微博 / X / Telegram）会把 🔺 原样渲染出来，与站内 SVG 图标风格不一致
- 影响范围：只要 md 首行摘要含 emoji 的任务都会中招（当前 1 个任务 / 2 处）

**这违反本文件 B1-6，因此是阻塞项。** 归属：**架构师 + 渲染层**（不在本轮授权的 2 个 CSS 文件内）。
建议修法：meta/og description 生成路径复用同一份 emoji→SVG 映射表，
或至少在 head 注入前统一剥离 emoji 码位（meta 是纯文本，无法放 SVG）。

**处置建议**：`scan_compliance.py` 的 emoji 扫描当前只扫组件层 CSS，
建议补一条**产物级**扫描：构建后正则扫全部 HTML 的 `<head>` 段，发现 emoji 即 fail。

## §C 一致性品控方法（可执行）

用户说「各个任务的风格还是不一致」——**根因是没有任何机制在 N 天 × 5 个任务上做交叉检查。**
以下是可落地的抽检流程，每步都有产物和判据，不靠「记得看一眼」。

### C-1 触发时机

| 时机 | 动作 | 耗时 |
|---|---|---|
| 每次改 `design-tokens*.css` | C-2 令牌门禁 + C-3 构建 | 2 min |
| 每次改 `site_blocks.css` / `detail-frame.css` | 全量 C-3 | 3 min |
| 每周 / 每次新增任务 | C-4 骨架抽检 + C-5 视觉抽检 | 20 min |
| 每次发版前 | C-2 + C-3 + C-4 | 25 min |

### C-2 令牌门禁（自动，改令牌必跑）

```bash
python3 scripts/test_dark_mode.py        # D-1 漏覆写 + D-2 对比度 + D-3 原语不可被改写
python3 scripts/scan_compliance.py       # B-1 全部可机检红线
```

`test_dark_mode.py` 的 D-1 是**这次 5 个 token 漏覆写事故的直接产物**——
把「靠人记得」变成「靠测试拦」。

### C-3 构建门禁（自动）

```bash
python3 scripts/build_site.py --stage _stage --base-url https://seaquake97.github.io/daily-market-pulse/
```

判据：零 `[fail]`、零异常退出。注意 `site_theme.blocks_css()` 带 `@lru_cache`，
**同一进程内改 CSS 后必须重启进程**，否则会读到旧内容（我本轮踩过这个坑）。

### C-4 骨架交叉检查（半自动，逐任务核对）

对 5 个任务详情页逐项打勾，**任何一项为「否」即阻塞发版**：

```bash
# A-1/A-2 骨架完备性：6 类 doc-meta 子组件 + 3 个必备区块是否全在
# 类名已对产物核验（stock-assistant.html 等），不是杜撰
for f in _stage/docs/daily/*/*.html; do
  [ "$(basename $f)" = "index.html" ] && continue
  echo "── $f"
  for k in doc-meta df-time df-kicker chip rating tl-sigma tag \
           verdict-card footer-note doc-title; do
    grep -q "$k" "$f" && echo "   OK   $k" || echo "   FAIL $k"
  done
done
```

> 注意：`daily/*/index.html` 是日页（不是详情页），详情页是 `daily/*/<任务>.html`，
> 上面已用 `basename != index.html` 过滤。C-3 的 `lru_cache` 坑同样适用。

检查表（人工判定部分）：

| # | 检查项 | 判据 | 阻塞 |
|---|---|---|---|
| C4-1 | 区块顺序 | A-2→A-3→A-4→A-5→A-6→A-7 无跳序无换序 | 是 |
