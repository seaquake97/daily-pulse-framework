# 多源行情容灾与降级数据契约规范（SPEC-DATA-FALLBACK）

> 契约版本：v1.0.0  
> 归档日期：2026-10-17  
> 状态：锁定（APPROVED）  
> 适用范围：daily-decision-engine / daily-pulse-framework 行情采集与合并链路

---

## 一、背景与定位

本项目每日定时研判流水线（09:28 竞价、11:00 盘面、14:30 指引、15:05 复盘、15:30 总复盘）的主数据源为腾讯自选股连接器（`westock-mcp`）。

当连接器由于网络波动、授权过期或运行环境限制处于不可用状态时，系统此前只能退化为纯数据缺口状态，导致日内持仓报告与关键指数断供。

参考 `ZhuLinsen/daily_stock_analysis` 的 `DataFetcherManager` 断路器与故障转移机制，本项目在 `framework/engine/collect/` 引入轻量级公开备用源（腾讯财经 Web、新浪财经 Web），在主源异常时提供只读行情兜底。

**受限例外原则（团队 P0 纪律）**：
- 备用源 HTTP 直取**仅在 MCP 连接器不可达时作为降级手段**；
- 启用备用源后，`market_data.json` 必须显式声明 `data_source: "fallback_public"` 并在 `data_gaps` 中明确记录，**严禁使用备用源数据冒充 MCP 主源数据（违反即 P0 事故）**。

---

## 二、降级保底字段与能力边界

备用源仅能提供高确定性的基础量价行情，**无法提供深度衍生数据**。主源与备用源能力边界如下表所示：

| 数据类别 | 字段名 | 主源（westock-mcp） | 备用源（腾讯/新浪） | 降级处理规则 |
|---|---|:---:|:---:|---|
| **指数行情** | `price`, `change_percent`, `change` | 支持 | 支持 | 备用源补齐，若缺失则进 gaps |
| **指数成交** | `amount` (成交额), `volume` (成交量) | 支持 | 支持 | 备用源补齐，单位统一归一化为手/元 |
| **指数均线** | `kline_close` (历史日K序列) | 支持 | 不支持 | 备用源无法提供，S3 动量相应降权 |
| **全市场宽度** | `up`, `down`, `limit_up`, `limit_down` | 支持 | 不支持 | 备用源不计算全市场宽度，S2 声明缺口 |
| **板块资金** | `sector_flows` (主力流入/流出) | 支持 | 不支持 | 备用源无法提供，S5 声明缺口 |
| **估值指标** | `pe_ratio`, `pb_ratio` | 支持 | 部分(不稳) | 备用源默认不填，避免估值失真 |
| **持仓个股** | `price`, `change_percent`, `amount` | 支持 | 支持 | 备用源补齐个股现价与涨跌，用于组合穿透 |

## 三、多源字段映射与方言适配标准

各公开接口存在编码、字段索引及单位不一致问题，必须在数据接入层（`quote_sources.py`）完成统一标准化：

### 3.1 腾讯财经接口规范（主备选）
- **接口地址**：`http://qt.gtimg.cn/q={codes}`（支持逗号分隔多代码批量请求，如 `q=sh000001,sz399001,sh600312`）
- **编码格式**：**GBK**
- **字段索引映射（波浪号 ~ 分隔，0基）**：
  - 索引 1：标的名称 (`name`)
  - 索引 2：证券代码 (`code`)
  - 索引 3：当前现价 (`price`)
  - 索引 4：昨收盘价 (`prev_close`)
  - 索引 5：今开盘价 (`open`)
  - 索引 30：行情时间戳 (`YYYYMMDDHHMMSS`，如 `20261016161500`)
  - 索引 31：涨跌额 (`change`)
  - 索引 32：涨跌幅百分比 (`change_percent`，单位 %，如 0.24 表示 +0.24%)
  - 索引 36：**成交量（单位：手）**（实测确认为手，禁止与成交额颠倒）
  - 索引 37：**成交额（单位：万元）**（需乘以 10000 转换为标准元）

### 3.2 新浪财经接口规范（副备选）
- **接口地址**：`http://hq.sinajs.cn/list={codes}`
- **防盗链要求**：请求头必须携带 `Referer: https://finance.sina.com.cn`
- **编码格式**：**GBK**
- **单位归一化铁律**：
  - 新浪接口存在单位分裂问题：**仅 `sh000xxx` 上证指数的成交量为手，其余深市指数、北交所指数及全部个股成交量均为股**。
  - 接入层必须对非 sh000 指数及个股除以 100 统一换算为手，防止成交量虚增 100 倍。

## 四、数据合并四大铁律（`merge_fallback.py`）

数据合并器必须严格遵循以下确定性契约：

1. **主源绝对优先**：
   - 逐字段检查：仅当 `market_data["indices"][code][field]` 为 `None` 或字段不存在时，才允许用备用源数据填补；
   - 主源已有有效数值（即使是盘前静态值），备用源绝不覆盖。
2. **脏值立即丢弃**：
   - 备用源数值必须通过基础校验：`price > 0` 且 `|change_percent| <= 20.0%`；
   - 遇到非正价格或异常涨跌幅，整条备用源记录直接丢弃，记入 `data_gaps`，绝不落盘污染数据。
3. **拿不到就声明缺口（严禁默认填0）**：
   - 备用源无法提供的字段（如 `pe_ratio`, `sector_flows`），直接保留缺失状态并在 `data_gaps` 中显式声明；
   - 严禁为了通过校验而私自填入 `0.0` 或伪造均值。
4. **持仓结构必须为 Mapping 对象**：
   - `market_data.schema.json` 严格规定 `holdings` 为字典对象（`{code: item}`）；
   - 合并持仓数据写回 `market_data["holdings"]` 时，必须使用 `positions_to_mapping()` 转换为以代码为 key 的字典，严禁直接塞入列表。

## 五、元数据写入与点分字段规范

合并完成后，通过 `apply_source_metadata()` 写入元数据：

```json
{
  "data_source": "fallback_public",
  "data_gaps": [
    "westock-mcp 连接器未连接：已自动启用公开合规行情源进行只读兜底。",
    "indices.sh000300.pe_ratio 缺失，备用源无法提供"
  ],
  "fallback_fields": [
    "indices.sh000001.price",
    "indices.sz399006.price",
    "holdings.sh600312.price"
  ]
}
```

- **`data_source` 枚举**：
  - `"primary_westock"`：主数据源采集完整。
  - `"fallback_public"`：成功通过备用源补齐了关键行情。
  - `"degraded"`：主源与备用源均未取得有效数据，完全降级。
- **`fallback_fields` 契约**：
  - 采用**点分路径**表示（如 `indices.sh000001.price`、`holdings.sz003816.price`），具备完备审计性；
  - 采用**累计去重**语义，保证多次调用的构建幂等性。

## 六、真缺口准则与任务态隔离

严禁过度报缺口导致系统陷入常态化伪降级：
- **真缺口**：交易时间段内该时点必需但未采到的数据（如盘中核心指数现价）；
- **任务态字段豁免**：
  - 外盘数据（`foreign`）与全市场总复盘数据仅在 15:05 收盘后采集；
  - 09:28 早盘竞价与 11:00 午盘分析中，不得将外盘未采集标记为数据缺口，避免误判降级态。

---

## 七、与 L-4 门禁契约衔接

金融场景最高合规要求：
- 当 `market_data["data_source"] == "fallback_public"` 或 `"degraded"`，或 `data_gaps` 非空时，下游报告生成模块**绝对禁止输出具体可执行的挂单买卖交易指令**（如“在 21.00 元挂单卖出 100 股”）；
- 必须强制软化为中性观察陈述（如“到达 21.00 元高抛观察区间，数据降级期间不发具体交易指令”）；
- `content_contract.py` 与 `check_report.py` 对此执行自动化硬门禁拦截，命中指令即阻断发布。
